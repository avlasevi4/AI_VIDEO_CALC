Релиз 3.1: «Мои проекты» всегда открывается как свёрнутая библиотека, а тарифы, пакеты и ручные ставки SYNTX синхронизируются между устройствами через защищённое облако владельца.

Релиз 08.09.2026: новая адаптивная навигация с иконками, крупные элементы управления, отдельная рабочая область проекта, цена заказчику в шапке и исходный логотип в favicon/PWA. Существующие расчёты и тарифы совместимы с обновлением.

Удаление теперь сохраняет `deletedAt` в облаке и локальной библиотеке. Версия 3.0 не восстанавливает такие проекты из старых локальных копий и проверяет отметку перед автосохранением. После перехода обновите приложение на всех устройствах: старый клиент v2 не понимает отметки удаления. Для защиты также от старых клиентов и одновременных запросов предусмотрен дополнительный серверный скрипт `supabase/protect-deletions.sql` (применяется отдельно через SQL Editor).

Правила навигации: [W3C WAI](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/), [Material navigation](https://github.com/material-components/material-components-android/blob/master/docs/components/BottomNavigation.md). Кнопки сохраняют текстовые подписи, текущий раздел отмечен через `aria-current`, клавиатурный фокус видим.

Локальная визуальная проверка: `node scripts/preview-server.mjs`, затем `http://127.0.0.1:8030/demo/`. Демо использует вымышленные проекты и заглушку облака; реальные данные Supabase не затрагиваются.

Mobile-first PWA-калькулятор себестоимости генерации видео в Kling AI и через SYNTX. Публичный расчёт работает как статический сайт, а именованные проекты владельца сохраняются локально и синхронизируются через защищённую базу Supabase.

## Архитектура

- `index.html` — доступная разметка интерфейса.
- `css/app.css` — mobile-first стили и адаптация для desktop.
- `js/calculator.js` — чистая расчётная логика без привязки к DOM.
- `js/pricing.js` — загрузка `pricing.json`, сетевое обновление и fallback на локальный кэш.
- `js/projects.js` — версионированная локальная библиотека проектов и migration старой одиночной сметы.
- `js/cloud.js` — авторизация владельца и синхронизация проектов с Supabase.
- `js/cloud-config.js` — публичные параметры подключения и UID единственного владельца.
- `js/app.js` — состояние интерфейса, история проектов, импорт/экспорт и PWA-регистрация.
- `data/pricing.json` — единая тарифная база.
- `supabase/schema.sql` — таблица проектов и deny-by-default Row Level Security.
- `vendor/supabase.min.js` — закреплённый browser SDK Supabase 2.112.3.
- `manifest.webmanifest` и `sw.js` — установка и offline-режим.
- `scripts/validate-pricing.mjs` и `tests/` — проверки тарифов, расчётов и библиотеки проектов.
- `android/` — нативная Android-оболочка с WebView, отдельной мобильной навигацией и безопасными сетевыми настройками.
- `artifacts/AI_VIDEO_CALC-Android-v1.0-debug.apk` — готовый APK для ручной установки и тестирования.

## Android-приложение

APK использует опубликованный GitHub Pages как единственный интерфейс и подключается к тому же Supabase-проекту. Поэтому после входа тем же e-mail и паролем внутри приложения доступны те же сметы, фактические расходы и завершённые проекты. Сессия WebView сохраняется внутри приложения, повторно вводить пароль при каждом запуске не нужно.

Android-оболочка добавляет верхнюю панель состояния, кнопки «Расчёт», «Проекты», «Обновить» и «Назад», экран отсутствия сети и системный выбор JSON-файла. Встроенный WebView принимает только HTTPS-страницы нашего GitHub Pages; посторонние ссылки передаются системному браузеру. Доступ к локальным файлам, незашифрованный HTTP и нативные JavaScript-мосты отключены.

Приложение использует первоначальный `AI_calc_logo.png` как значок, splash screen и логотип верхней панели. Исходники собираются из папки `android` командой `gradlew.bat assembleDebug` либо через Android Studio.

## Личные проекты и доступ владельца

Публичному посетителю доступны калькулятор и тарифы, но раздел проектов закрыт. После входа разрешённого владельца приложение загружает его проекты из PostgreSQL и поддерживает локальную offline-копию. Пароль обрабатывает Supabase Auth и он никогда не попадает в GitHub или таблицу проектов.

В каждой позиции сметы отдельно задаются количество готовых видео и количество генераций на одно готовое видео с учётом успешной попытки. Общее число платных генераций строки считается умножением этих значений: например, `6 × 3 = 18`. Оплата работы зависит от 6 готовых видео, а себестоимость генераций — от всех 18 попыток; глобального процентного резерва нет.

Все операции таблицы `projects` защищены одновременно двумя условиями:

- `auth.uid()` должен совпадать с `user_id` строки;
- `auth.uid()` должен совпадать с UID единственного разрешённого владельца.

Email владельца не хранится в репозитории. Публичный UID не является секретом: права выдаёт только проверенная Supabase-сессия и серверная RLS-политика.

Регистрации внутри приложения нет. Аккаунт владельца создаётся вручную, после чего публичную регистрацию в Supabase следует отключить.

### Подключение Supabase

1. Создайте Supabase project и выберите подходящий регион хранения.
2. В Authentication создайте единственного пользователя с e-mail и паролем, затем запретите публичные регистрации.
3. Укажите UID владельца в `supabase/schema.sql` и выполните файл в SQL Editor.
4. Заполните `supabaseUrl`, `supabasePublishableKey` и `ownerUserId` в `js/cloud-config.js`.
5. Используйте только publishable/anon key. `service_role` key запрещено помещать в браузерный код.

До заполнения конфигурации GitHub-сборка не показывает личные проекты. На `localhost` доступен явный локальный режим разработки для проверки интерфейса.

## Тарифная база

`data/pricing.json` отделяет провайдеров, модели, варианты и биллинг от интерфейса. Для каждого варианта указываются разрешение, аудио, допустимая длительность, статус и источник либо пояснение.

Поддерживаемые типы биллинга:

- `rate_per_second` — количество credits/tokens в секунду;
- `duration_table` — таблица стоимости для разрешённых длительностей;
- `fixed_generation` — фиксированная стоимость генерации;
- `manual_required` — публичный тариф не подтверждён, расход вводит пользователь.

Чтобы добавить модель, создайте запись в `models`, укажите существующий `provider`, уникальный `id` и массив `variants`. Чтобы добавить тип биллинга, реализуйте отдельную ветку в `billableUnits()` и тест в `tests/calculator.test.mjs`; UI использует общий результат и не требует переписывания.

## Достоверность данных

- `verified` — ставка сверена с указанным официальным источником;
- `manual` — значение перенесено из v1.2 либо задаётся пользователем;
- `unverified` — модель известна, но публичная ставка не подтверждена.

Пакеты Kling `10 $ / 660 credits` и SYNTX `1690 ₽ / 680 tokens`, а также старые ставки SYNTX перенесены из v1.2 и помечены `manual`. Подтверждённые ставки Kling 3.0 помечены `verified`; неподтверждённые 4K и большинство каталога SYNTX не угадываются и используют `unverified`/`manual_required`.

## Обновление тарифов

Кнопка «Обновить pricing.json» запрашивает свежий относительный файл GitHub Pages без кэша. При ошибке используется последняя копия из localStorage, а service worker хранит рабочий набор ресурсов offline. Workflow `.github/workflows/check-pricing.yml` только проверяет структуру и контрольные значения: он не переписывает цены и не запускает ненадёжный scraper.

## Локальный запуск

```bash
python -m http.server 8000
```

Откройте `http://localhost:8000/`. Для установки PWA нужен HTTP(S), поэтому открытие `index.html` через `file://` не подходит.

Проверки выполняются без сторонних зависимостей:

```bash
npm test
npm run check
```

## Локальные данные и синхронизация

Курс USD/RUB, параметры пакетов, ручные расходы SYNTX и offline-копия библиотеки проектов сохраняются в localStorage. Экспорт и импорт включают все проекты. При первом запуске приложение переносит старую одиночную смету v2 в проект «Проект до обновления», а также мигрирует параметры пакетов v1.2.

При входе локальная и облачная библиотеки объединяются по стабильному ID проекта. Более новая версия по `updatedAt` становится рабочей; локальные изменения отправляются в облако с небольшой задержкой. При недоступной сети интерфейс продолжает сохранять изменения локально и повторяет синхронизацию при следующем входе/запуске.

Каждый проект имеет статус `active` или `completed`. Завершение немедленно сохраняет статус и дату, сворачивает редактор и переносит карточку в группу завершённых проектов. Завершённый проект открывается в режиме просмотра и может быть возвращён в работу без потери сметы, фактических расходов или истории.

Service worker v2 использует новый cache name и удаляет старые кэши при активации, поэтому v1.2 не должна оставаться на экране после обновления.
